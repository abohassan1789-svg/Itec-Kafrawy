## 1) التقنيات والهيكل في Hr GAD (هنمشي على نفس الطريقة)

| البند | المستخدم في Hr GAD |
|---|---|
| الواجهة | **PySide6 (Qt)** — ستايل `Fusion` — اتجاه **RTL** للبرنامج كله |
| قاعدة البيانات | PostgreSQL عن طريق **psycopg 3** مباشرة (اتصال واحد autocommit بيتعاد فتحه لو وقع) |
| الإعدادات | ملف اتصال JSON + `.env` كاحتياطي |
| تشفير كلمة سر القاعدة | **Windows DPAPI** (`dpapi:...`) — عمرها ما بتتكتب نص صريح |
| كلمات سر المستخدمين | **PBKDF2-SHA256** بـ 240,000 دورة + salt |
| التقارير/الطباعة | reportlab + arabic-reshaper + python-bidi |
| الأيقونات | Emoji + qtawesome |
| الاختبارات | pytest |

**تقسيم الطبقات (Layers):**
```
app/
 ├─ config/        الإعدادات + ملف الاتصال + التشفير + رسائل أخطاء القاعدة
 ├─ database/      Database helper (psycopg) + إنشاء الـ schema تلقائي
 ├─ models/        تعريف الجداول (DDL)
 ├─ repositories/  كل الـ SQL هنا بس
 ├─ services/      قواعد العمل (مفيش SQL ولا واجهة)
 ├─ security/      تشفير كلمة السر + جلسة المستخدم (SESSION)
 └─ ui/
     ├─ common/    الثيم + عناصر مشتركة (هيدر المستخدم، كارت، رسايل الحفظ…)
     ├─ widgets/   عناصر قابلة لإعادة الاستخدام
     ├─ dialogs/   نوافذ حوار (بحث F1، تأكيد…)
     └─ screens/   الشاشات
```
**القاعدة:** الشاشة مابتكلمش القاعدة أبداً ← بتكلم Service ← بيكلم Repository.

## 3) نظام الصلاحيات وإدارة المستخدمين (هيتنقل كامل)

### 3.1 الجداول

| الجدول | الوظيفة | أهم الحقول |
|---|---|---|
| `roles` | **مجموعات الصلاحيات** | الكود، الاسم عربي/إنجليزي، الوصف، نشط |
| `app_users` | **المستخدمين** | اسم المستخدم (فريد)، كلمة السر مشفّرة، الاسم الكامل، **المهنة**، البريد، الهاتف، المجموعة، اللغة، **نشط / مدير / صلاحية كاملة**، ملاحظات، **الصورة**، آخر دخول |
| `permissions` | **كل الصلاحيات المتاحة** (بتتولّد تلقائي) | الكود `module.target.action`، النوع (شاشة/تقرير)، الموديول، الشاشة، الإجراء — بالعربي والإنجليزي، نشط |
| `role_permissions` | صلاحيات المجموعة | المجموعة، الصلاحية، مسموح، **كلمة سر الإجراء** |
| `user_permissions` | **تخصيص للمستخدم** فوق مجموعته | المستخدم، الصلاحية، مسموح/ممنوع، كلمة سر الإجراء |
| `user_login_logs` | سجل الدخول والخروج | المستخدم، وقت الدخول، وقت الخروج، الحالة (نجح/فشل)، الجهاز، السبب |

### 3.2 كود الصلاحية
`الموديول.الشاشة.الإجراء` — مثال: `crm.customers.edit`

**إجراءات الشاشات (13):** عرض · إضافة · تعديل · حفظ · حذف · **حذف الكل** · اعتماد · طباعة · تصدير · استيراد · **إظهار الإجماليات** · **ترحيل** · **إلغاء الترحيل**
**إجراءات التقارير (5):** عرض · معاينة · تصفية · طباعة · تصدير

> ترحيل / إلغاء الترحيل موجودين جاهزين — ودول بالظبط اللي محتاجينهم للقيود اليومية.

### 3.3 إزاي الصلاحيات بتتولّد (Registry + Sync)
- فيه ملف واحد (`permission_registry`) فيه كل الشاشات والتقارير.
- عند كل فتح للبرنامج **مزامنة**: أي شاشة جديدة تتضاف صلاحياتها، الأسماء تتحدّث، واللي اتشال **يتعطّل بس — عمره ما يتمسح**، وصلاحيات المجموعات والمستخدمين **ماتتلمسش**.
- يعني أي شاشة جديدة نعملها ← صلاحياتها بتظهر لوحدها في مصفوفة الصلاحيات.

### 3.4 حساب الصلاحية الفعلية (الأدق يكسب)
1. **مدير أو صلاحية كاملة** ← كل حاجة مسموحة.
2. غير كده ← نبدأ من **صلاحيات المجموعة**.
3. لو فيه **تخصيص للمستخدم** (سماح/منع) ← يغلب على المجموعة. لو مفيش ← يورث من المجموعة.

### 3.5 كلمة سر الإجراء
إجراءات حساسة (**حذف الكل**، **إظهار الإجماليات**) لما تتمنح لمجموعة أو مستخدم بيتحطلها **كلمة سر خاصة**، والبرنامج بيسألك عليها قبل التنفيذ. لو الصلاحية اتشالت ← كلمة سرها تتمسح.

### 3.6 الحماية
- كلمة السر مشفّرة PBKDF2 (مستحيل ترجع نص).
- **مايتقفلش ولا يتلغي آخر مدير فعّال** في النظام.
- اسم المستخدم مايتكررش (من غير حساسية لحروف كبيرة/صغيرة).
- المستخدم الموقوف مايقدرش يدخل ("هذا المستخدم موقوف، تواصل مع المدير").
- محاولات الدخول الفاشلة بتتسجل بالسبب.
- عند أول تشغيل بيتعمل **مدير افتراضي** تلقائي.

### 3.7 الجلسة (SESSION) والتطبيق على الشاشات
- بعد الدخول بتتحمّل كل أكواد الصلاحيات المسموحة في `SESSION`.
- أي شاشة بتسأل `SESSION.can("module.target.action")`:
  - القائمة الجانبية **مابتظهرش** الشاشة اللي مالكش "عرض" عليها.
  - لو حاولت تفتحها ← "ليس لديك صلاحية لفتح هذه الشاشة".
  - أزرار جديد/تعديل/حفظ/حذف/طباعة/تصدير **بتتعطّل** حسب الصلاحية.

### 3.8 شاشات إدارة المستخدمين (قسم "النظام والصلاحيات")

**① المستخدمين (`users`)**
- أزرار: مستخدم جديد · تعديل · حفظ · إيقاف/تفعيل · **سجل الدخول** · **معاينة الصلاحيات**.
- الفورم: اسم المستخدم · كلمة المرور (فاضية = بدون تغيير) · الاسم الكامل · المهنة · البريد · الهاتف · المجموعة · اللغة · نشط/مدير/صلاحية كاملة · ملاحظات · آخر دخول.
- **مربع صورة المستخدم** (رفع/إزالة — بتتحفظ مع "حفظ").
- قائمة المستخدمين: بحث بالاسم/البريد/الهاتف + "إظهار المستخدمين غير المفعّلين".
- لو المستخدم عدّل بياناته هو ← الهيدر فوق بيتحدّث على طول.

**② مجموعات الصلاحيات (`roles`)**
- يمين: قائمة المجموعات + بياناتها (جديد/تعديل/حفظ).
- شمال: **مصفوفة الصلاحيات** — صف لكل شاشة/تقرير، وعمود لكل إجراء:
  - **مترتبة زي القائمة الجانبية بالظبط** بعناوين الأقسام.
  - خانة على اسم القسم = تعلّم القسم كله مرة واحدة (ثلاثية الحالة).
  - الضغط على عنوان العمود = تعلّم الإجراء ده لكل الشاشات.
  - تحديد الكل · مسح الكل · **مزامنة الصلاحيات** · حفظ صلاحيات المجموعة.
  - بحث، وفلتر (شاشات/تقارير)، وإظهار الأقسام المخفية.
  - خانات كلمة سر الإجراء بعلامة 🔑.

**③ صلاحيات المستخدم (`user_permissions`)**
- اختيار المستخدم ← جدول بكل صلاحية: قيمة المجموعة · **التخصيص (وراثة / سماح / منع)** · **الصلاحية الفعلية** في الآخر.
- تغيير قسم كامل من صف اسمه.
- **تصفير التخصيصات** (يرجع للمجموعة) · **كلمة سر "حذف الكل" لكل شاشاته** مرة واحدة · 🔑 تعيين/تغيير لكل صلاحية.

### 3.9 ملف الاتصال
- JSON في `%ProgramData%\<اسم البرنامج>\connection.json` (أو `config/` وقت التطوير).
- فيه: وضع الاتصال (شبكة محلية/سحابة)، السيرفر والبورت، اسم القاعدة، المستخدم، **كلمة السر مشفّرة DPAPI**، sslmode.
- لو الملف مش موجود ← **شاشة إعداد الاتصال** تظهر أول مرة.
- `.env` كاحتياطي للتطوير.

2. **المدير الافتراضي:** أخلّي البرنامج يطلب تغيير كلمة السر أول ما يدخل بالحساب الافتراضي؟ (أنا بنصح بكده)
3. **قفل البرنامج من "تسجيل الخروج" بس** (زرار ✕ متشال) — نخليه زي Hr GAD؟
4. **العملة في الكروت والأرقام:** جنيه مصري (EGP / ج.م)؟

> ✅ **الإجابات (2026-11-07):**
> 1. البراند **A-H CODE**.
> 2. **مفيش** إجبار على تغيير كلمة سر المدير الافتراضي.
> 3. القفل من **"تسجيل الخروج" بس** زي Hr GAD.
> 4. العملة في الكروت **EGP**.
